# 交接文档：合并文明 v10（2026-11-28）

写给接手这个项目的 Claude Code。先读这一篇，再读 `docs/v10-balance-notes.md`（每项数值怎么测出来、为什么这么定）。

## 1. 项目是什么

《合并文明》是一款回合制的合并加城建游戏，设计者是 Rex。玩家在格子地图上摆建筑，3 座同种同级、挨在一起的建筑自动合成下一级；合成后占地会变大。玩家用建筑养活人口，靠人口升级村庄中心、推进时代。

现在的工作是 **v10 规则的原型和数值平衡**。主要用模拟器 `scripts/sim10.ts` 调数值，另有一个浏览器里可操作的测试版给 Rex 亲手试玩。

### 和 Rex 合作的方式

- Rex 用中文交流，回复要简短，先说结论，用表格对比各档数据。
- 改了数值就跑模拟器，给出对比表。常看的几项：
  - 压力曲线（各段有黄 / 有红的比例）
  - 合到 Lv10 的局数和大回合
  - 平均存活大回合
  - 每大回合合并次数
- 规则上有疑问先问 Rex，不要自己改。数值可以先试几档，推荐一个。
- 新开关默认关；Rex 选定以后再改默认值，并在 `docs/v10-balance-notes.md` 里记一笔。

## 3. 怎么跑

```bash
npm install
npm run dev                      # 测试版（首页是 v10，/v9.html 是旧版）
npx tsc --noEmit -p .            # 类型检查

# 模拟器：高手机器人 8 局，不跑无限行动力对照（快很多）
NOINF=1 BOTS=expert N=8 TURNS=600 npx tsx scripts/sim10.ts
```

### 模拟器的环境变量

| 变量 | 作用 |
|---|---|
| `SET=k=v,...` | 临时改 `RULES` |
| `SET=MERGE.x=` / `CORE.x=` | 改合并规则 / 村庄中心规则 |
| `SET=W.fam=` | 改某种建筑的出现权重 |
| `SET=PROD.x=` | 改基础产量倍数 |
| `SET=MIX.x=` | 改需求加权 |
| `RATIO=1` | 打印每个大回合的最低供需比 |
| `PW=1` | 统计电红的回合 |
| `LVSTAT=1` | 打印各级建筑数量 |
| `PICK=old\|priority` | 机器人选合并的方式 |
| `MAKE_ROOM=0` | 关闭腾位置 |
| `NOINF=1` | 不跑无限行动力的对照 |

高手机器人一局大约 3 秒。几档对比可以用后台 `&` 并行跑，再 `wait`。

## 4. v10 规则要点（以代码为准）

### 回合

- 1 个大回合 = 3 个小回合。人口每个小回合自然增长。
- 开局和每个大回合开始时，自动发完本回合的建筑（`autoDeal`）。
- 行动力只用来移动、旋转、买地。
  - 移动或旋转的花费 = 占地格数。
  - 合并有返还。

### 发牌

- 每次随机挑 3 种建筑，按固定权重直接发，不用选卡。
- 帮玩家补缺口的权重在第 10 个大回合降到 0。
- 每种建筑只发它在地图上自己最高的两级（按每种建筑分开算）。
  - 例：田地到 8 级就发 7、8 级，住房到 5 级就发 4、5 级。
- 两级以外的零头，只从最低一级补成 3 的倍数（`autoFillLow`）。

### 落地和仓库

- 新建筑随机落地（`landRandom`）。
- 放不下的进仓库。仓库按座数算：初始 5 座，每个时代 +2。

### 合并

- 3 座同种同级、挨在一起，放下就立刻合并。一次合 9 座直接升 2 级。
- 合并后产出 ×3×1.2（`MERGE.produceGain`）。
- 合并上限 `mergeCap` = max(村庄中心等级, 时代 + 2)。
  - 超过上限的组不合；村庄中心升级或进入新时代时一次全合。
  - 测试版会在这种组上标出原因。

### 村庄中心

- 只有一座，不能合并。安居人口够、原料够付升级花费时才能升级。
- 时代跟着村庄中心的等级走。
- 测试版里是手动按钮升级（`manualCoreUp`）；模拟器里条件满足就立刻升，效果一样。

### 资源

- **每回合重新算、不累积**：住房、粮食、幸福、生活用品。
- **有库存**：原料（木、石、铜、铁、煤、电）。库存主要用来付村庄中心的升级花费。
- **不同等级吃不同原料**（`tierInputs`）：
  - 木头这条线：Lv8 以下吃木，Lv8 起吃煤。
  - 石头这条线：Lv1–2 吃石，Lv3–4 吃铜，Lv5 起吃铁。
  - 产原料的建筑也按同样的等级换产出。
- **用电**：Lv9 起的建筑用电，缺电按比例减产。
  - 第一座用电建筑出现、地图上还没有电厂时，下一次发牌保证有电厂（`plantGuarantee`）。
- **生活用品**：第 2 个时代起需要，不够扣幸福。
- **红黄绿灯**：供给 ÷ 需求 ≥ 1.25 绿，≥ 1 黄，< 1 红。
  - 原料的供给 = 本回合产出 + 库存 ÷ 3。
  - 只统计地图上有建筑在用这种原料的回合。

### 每人需求

- 从第 5 个大回合起，用 10 个大回合加到 ×2.5（`needMult`）。
- 四样分开加权（`needMix`）：粮食 1.8，住房 1.5，生活用品 1.5，幸福 0.7。
- 另外每升一级村庄中心 ×1.08（`needPerLevel`）。

### 输赢

- 人均幸福连续 2 回合低于失败线就 Game Over。

## 5. 当前默认值和理由（摘要，详见 balance notes）

| 设置 | 值 | 理由 |
|---|---|---|
| `landRandom` | true | 原来落在最好合的位置，45% 的合并不用动手，太便宜 |
| `cardTopLevels` / `cardTopRef` | 2 / 'family' | 按每种建筑分开算，低级链不被高级卡淹没 |
| `dealFamilies` | 3，固定权重 | Rex 定：不追缺口，一次发 9 张同种太多 |
| `dealNeedTurns` / `dealNeedWeightEnd` | 30 / 0 | 补缺口在第 10 个大回合前退出，之后才有压力 |
| 仓库 | 5 座，每时代 +2 | 丢弃主要是因为地图碎片化，不是缺行动力 |
| `MERGE.produceGain` | 1.2 | 原来的倍率让基础资源永远是绿的 |
| `apBase` | 24 | 每个大回合 8–9 次合并 |
| `needMult` 等 | 见上一节 | 让黄灯在第 10–15 个大回合开始出现 |
| `popRate` | 0.025 | 配合需求加倍，Lv10 的局数不掉 |
| `prodMult` | 电 ×2，铁 ×0.6 | 早期原料一直绿是正常的；铁在它被用的那段时间里要有压力 |
| 电厂权重 | 5 | 电是最常见的红灯 |
| `capMode` | 'era' | 只看村庄中心等级时，前期什么都合不了 |
| `autoDeal` | true | Rex 定；中期黄灯更接近目标 |

### 当前结果（高手机器人，8 局）

| 指标 | 结果 |
|---|---|
| 每大回合合并 | 约 8.3 次 |
| 合到 Lv10 | 5/8 局，约第 45 个大回合 |
| 平均存活 | 约 58 个大回合 |
| 第 11–30 个大回合 | 有黄 26%，有红 9% |
| 第 31–60 个大回合 | 有黄 51%，有红 34% |

## 6. Rex 定下的偏好和不要改的东西

- 新建筑随机落地。
- 发牌按每种建筑自己地图上最高的两级；零头从最低级补成 3 的倍数。
- 发牌不追缺口，按固定权重随机 3 种。
- 村庄中心保持单座，按人口和原料升级，不做成可合并的建筑。
- 正式 UI 里，村庄中心满足条件时提示，由玩家按一下升级；升级时把挨着却没合的组一次合掉。
- 原料只在某几个时代有用，过了那段不再统计；早期原料一直绿是正常的。
- 仓库以后可以做成局外升级项（基础容量，每个时代扩大）。
- 后台动态难度（`ddaStep`）可以偷偷调，但现在默认关。
- 机器人选合并的优先级：
  1. 先选能赚行动力的；
  2. 再选不亏的；
  3. 都要亏时，红灯资源优先，缺得越多越优先；黄灯按离变红有多近来加权。
- 美术：不用阿拉伯风格（这一条是从项目聊天转来的，不是从代码里看出来的）。

## 7. 已知问题和下一步

1. **合出 Lv10 偏早。** 高手机器人约第 45 个大回合，目标是熟练玩家 60–90。
   - 可以用新手和普通机器人对照，或者放慢后期节奏。
2. **每局都以失败告终。** 第 60 个大回合以后几乎全红，需要设计一个收尾或通关条件。
3. **电红还有约 9%。** 剩下的主要是用电建筑多了以后真的不够。
4. **测试版是给 Rex 试玩用的简易界面，还缺：**
   - 撤销；
   - 建筑说明和图鉴；
   - 适配手机触屏（拖动已经能用，但没在手机上测过）。
5. **数值多是占位值。** 原料种类和建筑链的收支表里有些还没填，见 `data.ts` 里的注释。
6. **库存规则还没定。** 原料库存目前没有上限；Rex 暂时不要改升级花费的付法。
