# v10 数值测试小结（2026-11-28）

本文记录这一轮模拟测试做了什么、看到了什么，以及现在每项默认设置为什么这么定。

- 模拟器：`scripts/sim10.ts`
- 数值：`src/v10/data.ts`（`RULES`、`MERGE`、`CORE`、`FAMILIES`）
- 下文的数据都来自高手机器人（expert），6–8 局取平均，`TURNS=600`
- 一个大回合 = 3 个小回合

## 目标（Rex 定的）

- 每个大回合合并 5–10 次；高手 60–90 个大回合合出 Lv10；丢弃的建筑尽量少。
- 资源压力：
  - 大约一半的回合有黄灯；
  - 不到 30% 的回合有红灯；
  - 两项红算危险。
- 压力节奏：前 10 来个大回合基本没压力，第 10–15 回合开始出现黄，越往后越紧。
- 缺的资源种类要均衡，不能总是同一样缺。

## 一、发卡与落地

| 改动 | 原因 / 结果 | 默认 |
|---|---|---|
| 新建筑随机落地 | 原来放在最方便合并的位置，45% 的合并一步都不用移动，太便宜。改成随机后只剩 5%，移动建筑成了真实成本。 | `landRandom: true` |
| 只发每种建筑自己地图上最高的两级 | 原来按全局最高级发，低级链会被高级卡淹没。改成按每种建筑分开算（田地到 8 级发 7、8 级，住房到 5 级发 4、5 级）后，6/6 局都合到了 Lv10，丢弃也少了。 | `cardTopLevels: 2`，`cardTopRef: 'family'` |
| 两级以外的低级建筑只从最低一级补成 3 的倍数 | Rex 的规则：留下的零头给一次凑整的机会，之后不再发。 | `autoFillRef: 'card'` |
| 直接发牌：每次随机 3 种，按固定权重 | 原来一次发 9 张同种，太多。现在玩家拿到什么拼什么，不用再选卡。 | `dealFamilies: 3`，权重见 `FAMILIES.weight` |
| 补缺口提前退出 | 原来发牌会追着缺口补，资源几乎永远是绿的。现在补缺口的权重在第 30 个小回合（第 10 个大回合）降到 0，之后完全按固定权重发。 | `dealNeedWeight: 1 → dealNeedWeightEnd: 0`，`dealNeedTurns: 30` |
| 权重调整 | 铁和电的红灯太多，所以多发采石场（2.5）和电厂（5）。木材也缺，伐木场调到 2，住房调到 1.5。 | 见 `FAMILIES` |

## 二、仓库

- **从按格子改成按座数。** 丢弃的建筑主要不是因为缺行动力：一是地图碎片化放不下，二是大建筑超过 6 格进不了仓库。按座数算以后，大部分丢弃消失了。
- **容量：** 初始 5 座，每个时代 +2，也就是 `warehouseSlots: 5`、`warehouseSlotsPerEra: 2`。
- **仓库总是会被放满。** 每局的峰值都顶到上限，所以容量本身就是一个手感旋钮。以后可以做成局外升级。

## 三、合并

- **产出倍率：1.2。** 每次合并后，产出和消耗都是 ×3×1.2，也就是 `MERGE.produceGain: 1.2`。原来的倍率让基础资源一直是绿的，降到 1.2 以后中期压力变大了。
- **合并成本按完整计算。** 一座建筑从落地到合并，花在它身上的所有移动都算进成本。之前只看最后一步，误以为合并几乎免费，这个结论已经更正。
  - 随机落地以后，64–69% 的合并会亏行动力。
- **机器人怎么选合并（Rex 的规则）：**
  1. 先选能赚行动力的；
  2. 再选不亏的；
  3. 都要亏的时候：红灯资源最优先，缺得越多越优先；黄灯资源按离变红有多近来加权。
- **腾位置。** 放不下时，机器人会先挪开其他建筑。
- **行动力：24。** `apBase: 24` 比 20 每个大回合多出 1 次左右的合并，现在是 8–9 次。

## 四、资源压力

各资源的供需比（供给 ÷ 需求）怎么判灯：

| 供需比 | 灯 |
|---|---|
| ≥ 1.25 | 绿 |
| ≥ 1 | 黄 |
| < 1 | 红 |

原料的供给按“本回合产出 + 库存 ÷ 3”算。

### 1. 为什么中期一直没有黄

加了统计 `RATIO=1`，看每个大回合各资源最紧时的供需比。原来第 10–30 回合：

| 资源 | 供需比 |
|---|---|
| 住房 | 4–6 倍 |
| 粮食 | 5–8 倍 |
| 幸福 | 3.5 倍 |

离黄灯差得很远，所以下面这些调整都碰不到这一段：

- 补缺口提前退出
- 多给行动力
- 需求随等级增长更快（1.2）

### 2. 试过的做法

| 做法 | 结果 |
|---|---|
| 需求随村庄中心等级增长更快（1.4–1.8） | 指数增长后期太狠：第 30 回合左右因为幸福不够就失败，几乎合不到 Lv10。 |
| 需求整体乘倍数，四样一起乘 | 只有幸福先变紧，而幸福也是导致失败的那一项，局变得很短。 |
| 需求整体乘倍数，四样分开加权 | 粮食加得最多，住房和生活用品其次，幸福最少。四样差不多同时变紧。 |
| 降低住房、粮食、幸福的基础产量 | 前期变紧了，但到第 15 回合供给仍是需求的 2–3 倍。人口按固定速度增长，一直落后于供给，机器人还能靠合并补回来。效果很小。 |
| 人口增长加快到 3% | 整局节奏变快，Lv10 6/8，大约第 41 回合，但中期还是几乎没有黄。原因是发牌数量跟人口挂钩，人越多供给也越多。 |
| 人口增长 2.5% + 需求加倍 + 电厂加强 | 最好的平衡，见下表。 |

### 3. 对比（每档 8 局）

| 做法 | 第 11–30 回合有黄 / 有红 | 第 31–60 回合有黄 / 有红 | 合到 Lv10 | 平均存活 | 电红 |
|---|---|---|---|---|---|
| 不加需求（旧默认） | 0% / 0% | 34% / 31% | 4/6，第 50 回合 | 约 57 回合 | 52% |
| 需求 ×2.5，增长 1.08 | 14% / 5% | 53% / 35% | 3/8，第 50 回合 | 约 50 回合 | 47% |
| 基础产量约减半 | 1% / 1% | 38% / 23% | 2/8，第 50 回合 | 约 54 回合 | 47% |
| 人口增长 3% | 4% / 4% | 45% / 31% | 6/8，第 41 回合 | 约 51 回合 | 23% |
| **现默认：人口 2.5% + 需求 ×2.5** | **14% / 5%** | **47% / 28%** | **5/8，第 45 回合** | **约 55 回合** | **17%** |

### 4. 现在的默认

| 设置 | 默认值 | 说明 |
|---|---|---|
| `needMult` | 2.5 | 每人需求的整体倍数 |
| `needMultFrom` | 5 | 从第 5 个大回合开始加，前 5 回合不受影响 |
| `needMultRamp` | 10 | 用 10 个大回合慢慢加满 |
| `needMix` | 粮食 1.8，住房 1.5，生活用品 1.5，幸福 0.7 | 加出来的部分按项分配。幸福本来就最紧，所以少加 |
| `needPerLevel` | 1.08 | 每升一级村庄中心，每人需求 ×1.08，从 2 级起算（`needFromLevel: 2`） |
| `popRate` | 0.025 | 人口每回合按比例增长 2.5% |
| `prodMult.power` | 1.5 | 电厂产电 ×1.5；电厂权重同时调到 5 |
| `prodMult` 其他项 | 1 | 建筑基础产量的旋钮，默认不改 |

## 五、其他已有机制（之前定的）

- **生活用品（goods）**
  - 从第 2 个时代开始需要，用 30 个回合慢慢加到位；
  - 冶炼厂生产生活用品；
  - 不够时扣幸福。
- **用电**
  - 建筑 Lv9 以上开始用电；
  - 电不够时，产出按缺电的比例下降。
- **村庄中心升级门槛**：从 3 级起 ×3（`coreSettledMult`）。
- **前期幸福来源**：村庄中心自带幸福（`coreHappy: 2`），避免 1 级时就崩。
- **晚出现的建筑链起点更高**：起始数值按 `startScale: 0.5` 抬高，阶段跳级也会照顾到（`stageJump`）。
- **后台偷偷调难度**：已经写好，默认关（`ddaStep: 0`）。
  - 打开后从第 10 个大回合起生效：一直全绿就少发一点，两项红就多发一点。
  - 实测高手在供给降到 0.27 倍时中期仍然是绿的，所以暂时没开。

## 六、还没解决的问题

1. **原料几乎没有压力。**
   - 木、铜、铁一直是绿的，因为库存越堆越多，铜的供需比最高到几百倍。
   - 要让原料也紧，需要单独调产量，或者改库存规则（比如设上限、按回合损耗）。
2. **合出 Lv10 偏早。**
   - 高手机器人大约第 45 个大回合就合出 Lv10，目标是 60–90。
   - 真人一般比机器人慢，所以先没压。之后可以用新手和普通机器人对照，再决定要不要放慢。
3. **每局最后都会失败。**
   - 第 60 回合以后几乎全是红灯，失败的直接原因多是幸福不够。
   - 后期需要给玩家一个收尾或者喘息的机制。

## 七、模拟器用法

```
BOTS=expert N=8 TURNS=600 npx tsx scripts/sim10.ts
```

### 环境变量

| 变量 | 作用 |
|---|---|
| `RATIO=1` | 输出每个大回合的最低供需比 |
| `LVSTAT=1` | 输出各级建筑数量 |
| `PICK=old\|priority` | 机器人选合并的方式 |
| `MAKE_ROOM=0` | 关闭腾位置 |
| `NOINF=1` | 不跑无限行动力的对照 |

### SET 改参数

用法：`SET=k=v,k2=v2`

| 写法 | 改什么 | 例子 |
|---|---|---|
| `k=v` | `RULES` 里的项 | `apBase=24` |
| `MERGE.x=` | 合并规则 | `MERGE.produceGain=1.2` |
| `CORE.x=` | 村庄中心 | `CORE.plotsPerLevel=4` |
| `W.fam=` | 某种建筑的出现权重 | `W.plant=5` |
| `PROD.x=` | 基础产量倍数 | `PROD.food=0.5` |
| `MIX.x=` | 需求加权 | `MIX.happy=0.7` |
